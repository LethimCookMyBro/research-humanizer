# สำนวนวิจัยและการแปล

## R07 ใช้สำนวนเฉพาะกับเนื้อความของบทความ

ใช้ภาษาระดับกลางค่อนทางการ เหมือนนักวิจัยอธิบายในห้องบรรยาย เลือกคำที่คุ้นเคยและกริยาตรงไปตรงมา ใช้ศัพท์เฉพาะเมื่อช่วยรักษาความแม่นยำ ใช้คำสำคัญให้คงที่ ไม่เปลี่ยนคำไปเรื่อย ๆ เพียงเพื่อหลีกเลี่ยงการซ้ำ

ใช้ประโยคสั้นที่สมบูรณ์และมีใจความหลักหนึ่งเรื่องเป็นส่วนใหญ่ แยกประโยคที่รวมกลไก ผล และการตีความไว้ด้วยกัน ใช้ลูกน้ำเมื่อจำเป็นทางไวยากรณ์ แต่ไม่ร้อยอนุประโยคยาวหลายชั้น ความยาวประโยคควรเปลี่ยนตามเนื้อหา ไม่ทำทุกประโยคหรือทุกย่อหน้าให้มีรูปแบบตายตัว

ห้ามใช้เครื่องหมายอัฒภาคและทวิภาคในเนื้อความทั่วไป อนุญาตป้าย `Keywords:` และรายการอ้างอิง ห้ามใช้ em dash และ en dash หรือขีดคู่ที่เว้นวรรคเป็นตัวคั่นประโยค เขียนช่วงด้วยคำ เช่น `ถึง` หรือ `to` รักษาขีดสั้นที่เป็นส่วนของคำ เครื่องหมายลบ และเครื่องหมายทางคณิตศาสตร์ที่จำเป็น

เลี่ยงวงเล็บที่แทรกคำอธิบายกลางประโยค ย้ายคำอธิบายเป็นประโยคใหม่ได้ วงเล็บสำหรับการอ้างอิง การอ้างหมายเลขสมการ การจัดกลุ่มทางคณิตศาสตร์ และการแนะนำคำย่อที่จำเป็น ไม่ใช่วงเล็บตกแต่ง หากแนะนำคำย่อด้วยประโยคธรรมดาแล้วอ่านดีกว่าให้ใช้วิธีนั้น

ห้ามใช้คำย่อแบบ contraction ในภาษาอังกฤษ ใช้ `is not`, `does not`, `cannot`, `we have` และ `it is` ห้ามลบเครื่องหมายแสดงความเป็นเจ้าของ รักษาข้อความอ้างตรง ชื่อผลงาน รหัสเฉพาะ และข้อมูลต้นทางเมื่อการแก้จะทำให้ผิดจากแหล่งเดิม ให้ปรับประโยครอบข้างหรือถอดความอย่างซื่อตรงแทน

ใช้อักษรกรีกและสัญลักษณ์ เช่น `°`, `±` และ `≤` เฉพาะในสัญกรณ์คณิตศาสตร์ นิพจน์ตัวเลข ตาราง หรือป้ายเชิงตัวเลขในกราฟ สมการที่อยู่ในบรรทัดถือเป็นคณิตศาสตร์ ในเนื้อความทั่วไปให้เรียกชื่อปริมาณ กำหนดความหมายเมื่อใช้สัญลักษณ์ครั้งแรก และใช้ความหมายนั้นตลอด

แบ่งย่อหน้าตามหน้าที่ หัวข้อที่มีเนื้อหาจริงควรมีหลายย่อหน้าอ่านง่าย แต่ไม่เพิ่มคำเพื่อบังคับให้หัวข้อสั้นมีหลายย่อหน้า ห้ามปล่อยหัวข้อไว้ท้ายหน้าโดยเนื้อหาเริ่มอีกหน้า Contributions ต้องเป็น bullet สั้นและไม่มีตัวเลขผลการทดลอง ใช้หัวข้อและตัวหนาเท่าที่ช่วยค้นหรือเข้าใจเนื้อหา

กฎสำนวนไม่ให้แก้ไวยากรณ์ของโค้ด YAML คำสั่ง LaTeX สมการ URL รหัส ข้อมูลบรรณานุกรม หรือข้อความอ้างตรง กฎนี้ครอบคลุมเนื้อความในชื่อเรื่อง คำบรรยายภาพ หมายเหตุตาราง และคำอธิบายในภาพด้วย การคงรูปแบบเทคนิคไม่ใช่ช่องทางนำเนื้อความธรรมดาไปใส่เป็นโค้ดเพื่อหลบกฎ

## R08 ตัดข้อความลอยโดยไม่ทำให้วิทยาศาสตร์ผิด

เมื่อย่อหน้าไม่มีประเด็นชัด ให้เขียนใหม่ทั้งย่อหน้า ไม่เปลี่ยนเพียงคำที่ดูเป็น AI ทุกประโยคที่เก็บไว้ควรเพิ่มข้อเท็จจริง คำจำกัดความ ข้ออนุมานที่มีเหตุผล การเชื่อมประเด็นที่จำเป็น หรือข้อจำกัดที่มีผลต่อการตีความ

| รูปแบบที่ควรตรวจ | วิธีแก้สำหรับงานวิจัย |
| --- | --- |
| สร้างคู่ตรงข้ามที่ไม่จำเป็น | กล่าวประเด็นตรง ๆ และเก็บการเปรียบเทียบที่มีสาระ |
| ประโยคปิดย้ำความสำคัญ | เก็บเฉพาะผลหรือข้อสรุปใหม่ |
| ถ้อยคำดูหนักแน่นแต่ไม่ชัด | ระบุคำถามทางเทคนิคจริง |
| ประโยคเกริ่นว่าจะอธิบาย | เริ่มจากปัญหา เงื่อนไข หรือผล |
| โต้แย้งคนที่ไม่มีอยู่ | กล่าวเฉพาะทางเลือกหรือข้อกังวลที่เกี่ยวข้อง |
| บังคับให้ทุกเรื่องมีสามข้อ | ใช้จำนวนประเด็นตามเนื้อหาจริง |
| เริ่มประโยคซ้ำต่อเนื่อง | ปรับโครงสร้างโดยไม่ซ่อนผู้กระทำ |
| ใช้เครื่องหมายคั่นมาก | เขียนเป็นประโยคสมบูรณ์ |
| ซ้อนคำเผื่อหลายชั้น | เก็บระดับความไม่แน่ใจที่หลักฐานต้องการ |
| ใส่ขีดในคำตามสูตร | ใช้ตามไวยากรณ์และชื่อทางเทคนิค |
| ประโยคกรรมวาจกที่ไม่รู้ว่าใครทำ | ระบุผู้กระทำเมื่อมีผลต่อความเข้าใจ |
| คำใหญ่ที่ไม่เพิ่มความหมาย | ใช้คำธรรมดาที่แม่นยำ |
| ยกความสำคัญเกินหลักฐาน | ระบุผลที่แสดงได้จริง |
| บอกว่ามีความเกี่ยวข้องแบบลอย ๆ | ระบุความสัมพันธ์เฉพาะเมื่อทราบ |
| เติมท้ายประโยคด้วยการตีความ | ตัดส่วนที่ไม่มีหลักฐานรองรับ |
| ภาษาขายผลงาน | ระบุความสามารถและเงื่อนไขที่ทดสอบ |
| อ้างผู้เชี่ยวชาญไม่ระบุชื่อ | อ้างแหล่งจริงหรือตัดข้อความ |
| กริยาหลายคำแทนคำตรง | ใช้กริยาตรงเมื่อความหมายเท่ากัน |
| ป้ายตัวหนาซ้ำทุกข้อ | ใช้ย่อหน้าหรือตารางที่มีหน้าที่จริง |
| หัวข้อเพื่อความสวยงาม | ตั้งชื่อตามเนื้อหา |
| เครื่องหมายคำพูดไม่สม่ำเสมอ | ใช้รูปแบบเดียวกับต้นฉบับ |
| คำทักทายหรือข้อเสนอแบบแชต | ตัดออกจากบทความ |
| บอกว่าไม่รู้แล้วเดาต่อ | ระบุข้อมูลที่แหล่งไม่ได้ให้ |
| ประโยคแรกพูดซ้ำชื่อหัวข้อ | เริ่มด้วยเนื้อหาจริง |
| เล่าว่าแก้เอกสารอย่างไร | ย้ายไปบันทึกการแก้ |
| อธิบายพื้นฐานที่ผู้อ่านไม่ต้องการ | เก็บเฉพาะบริบทที่ช่วยอ่านงานนี้ |

รายการนี้เป็นแนวตรวจแก้ ไม่ใช่หลักฐานว่าใครใช้ AI ห้ามแบนศัพท์วิทยาศาสตร์เพราะปรากฏในงานเขียนทั่วไปด้วย รักษาคำว่าความสัมพันธ์สำหรับผลเชิงสังเกต ใช้คำว่า robust เมื่อมีนิยามและการประเมินความทนต่อเงื่อนไขรบกวน และใช้คำว่ามีนัยสำคัญเมื่อมีการวิเคราะห์ที่รองรับ ห้ามเปลี่ยนความสัมพันธ์เป็นเหตุและผลเพื่อให้ประโยคดูตรงขึ้น

รักษาการใช้คำซ้ำที่จำเป็นต่อคำนิยาม การเปรียบเทียบ และการติดตามเรื่อง รักษาความไม่แน่นอน ผลที่ไม่เป็นไปตามคาด ข้อยกเว้น และความต่างระหว่างความสัมพันธ์ กลไก การทำนาย และเหตุและผล หากข้อความเดิมผิดหรือไม่มีหลักฐาน ให้แจ้งและแก้ด้วยหลักฐาน หรือตัดพร้อมบันทึกเหตุผล การรักษาความหมายไม่ได้บังคับให้เก็บข้อผิดพลาดที่ตรวจพบแล้ว

## R09 ทำให้ฉบับไทยและอังกฤษตรงกันทางวิชาการ

ทำรายการศัพท์ที่ระบุคำไทย คำอังกฤษ คำย่อ คำนิยาม และคำทางเลือกที่อาจทำให้เข้าใจผิด ภาษาไทยต้องเป็นประโยคไทยตามธรรมชาติ ไม่เรียงคำตามภาษาอังกฤษ ภาษาอังกฤษต้องเป็นภาษาวิชาการที่ตรง ไม่แปลคำเชื่อมไทยตามตัว

กำหนดก่อนว่าฉบับใดเป็นต้นฉบับหลัก รักษาตัวเลข หน่วย หมายเลขสมการ อ้างอิง หมายเลขภาพ คำปฏิเสธ ทิศทางการเปรียบเทียบ ความไม่แน่นอน และขอบเขตข้อสรุปให้ตรงกัน ห้ามแปลคำที่หมายถึงความเป็นไปได้ให้เป็นข้อยืนยัน เปลี่ยนความสัมพันธ์เป็นเหตุ หรือขยายผลจากกลุ่มที่ทดสอบเป็นทุกกรณี

อธิบายศัพท์จำเป็นสั้น ๆ เมื่อใช้ครั้งแรก ไม่ใส่คำอังกฤษในวงเล็บตามหลังคำไทยทุกครั้ง ใช้ชื่อส่วนประกอบและตัวชี้วัดตรงกันในเนื้อหา สมการ โค้ด และภาพ

เมื่อทำบทความคู่ภาษา ให้เก็บรายการจับคู่หัวข้อ และแก้ทั้งสองฉบับเมื่อสาระเปลี่ยน ความหมายที่ยังไม่ตรงกันเป็นปัญหาที่ต้องตรวจ ไม่ใช่เหตุให้เลือกประโยคที่ฟังลื่นกว่า

## R30 ใช้กฎกับสถานการณ์จริง

ตัวอย่างต่อไปนี้สาธิตการเขียนและการตัดสินใจ ไม่ใช่ผลของโครงการผู้ใช้ ใช้ข้อความตัวอย่างได้เฉพาะเมื่อหลักฐานของโครงการรองรับ

| ข้อความอ่อนหรือเกินหลักฐาน | วิธีเขียนที่ป้องกันความเข้าใจผิด |
| --- | --- |
| ระบบที่เสนอยกระดับประสิทธิภาพอย่างก้าวกระโดด | วิธีนี้รวมขั้นเตรียมข้อมูลและขั้นประมาณค่าไว้ในกระบวนการเดียว |
| ผลพิสูจน์อย่างชัดเจนว่าระบบทนทาน | ระบบได้รับการประเมินภายใต้เงื่อนไขสัญญาณรบกวนที่ระบุ |
| วิธีนี้ไม่เพียงแม่นยำ แต่ยังมีประสิทธิภาพ | รายงานความแม่นยำและต้นทุนคำนวณแยกกันตามหลักฐานจริง |
| ความสัมพันธ์นี้แสดงว่ามาตรการเป็นสาเหตุให้ดีขึ้น | พบความสัมพันธ์จากการวิเคราะห์ แต่การออกแบบนี้ยังไม่ยืนยันเหตุและผล |
| การทดลองอย่างครอบคลุมยืนยันว่าใช้ได้ทุกกรณี | ระบุการทดลองที่ทำจริงและจำกัดข้อสรุปตามเงื่อนไขนั้น |

เมื่อตารางกับไฟล์ผลไม่ตรงกัน ให้แสดงข้อขัดแย้งในบันทึกทำงานและตรวจขั้นคำนวณ ห้ามเลือกค่าเงียบ ๆ เมื่อโค้ดมีส่วนใหม่ที่ยังไม่ทดสอบ ให้ระบุว่าเป็นข้อเสนอหรือตัดออกจากระบบที่อ้างว่าประเมินแล้ว เมื่อไม่มีข้อมูลวัดจริง กราฟที่ดูเสร็จเรียบร้อยใช้แทนไม่ได้

เมื่อยังไม่ได้ทบทวนงานเพื่อยืนยันคำว่าดีที่สุดในปัจจุบัน ให้ระบุเฉพาะวิธีที่นำมาเทียบ เมื่อยังไม่คำนวณความไม่แน่นอน ห้ามเติมแถบเงาเพื่อให้กราฟดูดี เมื่อยังไม่ได้เปิด Word ให้รายงานการตรวจหน้าของ Word ว่ายังไม่ตรวจ
