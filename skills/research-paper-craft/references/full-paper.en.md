# Full-paper drafting

Use for an explicit whole-manuscript request, with ARS or standalone. Use the existing evidence, writing, methods, visuals and submission modules at the relevant phase. This contract applies to different researchers and disciplines, not one author's project.

For a scientific audit or substantive research decision, load [research reasoning](research-reasoning.en.md). Reuse the records below. Language-only edits do not require the full review.

## R41 Draft the whole source-bound manuscript

Full-paper means write the complete applicable manuscript, not just an outline and not a final rewrite pass over a generic AI draft. Start with the research question, article type, implemented work, available evidence, author decisions, venue and requested output. Read supplied materials before asking. A topic alone supports research and planning, not invented completed experiments.

Select one workflow owner. When ARS is requested, load [the adapter](ars-integration.en.md) before dispatch. Standalone is a separately declared option, not simulated ARS. Preserve an already-running workflow's state. Record mode as full-paper, revise or audit. Minimal editing is a rule for revision, not a limit on drafting new sections.

Build a compact plan connecting questions, contributions, evidence, metrics, sections and visuals. Use current literature and the actual venue template through [literature guidance](literature.en.md). Do not force an experimental structure or quantitative metrics onto theoretical, qualitative, review or methods work. A prototype description is not a completed evaluation.

Write evidence-bearing methods, equations, setup and results first where appropriate. Explain known choices without inventing their rationale. Build the discussion from the findings and limitations. Then write related work, the accessible Introduction, short nonnumeric contribution bullets, abstract and title. All requested applicable sections must contain source-bound prose. Section order in the final paper follows the venue, not the drafting order.

Humanize as each section is written. Give paragraphs scientific jobs, use stable terminology and preserve limits. Avoid an assembly of interchangeable mini-essays. Run a whole-paper consistency pass on questions, subjects, conditions, units, numbers, notation, references and summary claims. Review existing text minimally when it is already correct.

Missing study information triggers a focused researcher question. Mark the exact section and continue independent supported work. Record measurements as not measured when that is their actual status. Do not complete Results by importing published values, estimating hidden data or generating an attractive graph. A complete outline with empty sections is not a completed paper. Deliver the supported manuscript as a Working draft when essential evidence is still missing, with a separate gap list.

## R42 Use author context without inventing memory

Read the current brief, explicit user corrections, authorized project instructions, accessible memory and author-approved samples. Record which sources were actually available. Do not claim access to previous chats, Claude memory, Codex memory or another user's profile without reading them through the host. If memory is disabled or unavailable, say so only when relevant and continue with supplied context and house style.

Keep a per-project working folder such as `.research-humanizer/`, not inside the plugin installation. Keep it private and excluded from public version control. Use separate profiles for different researchers. Store prose preferences and locked terms apart from study facts. Do not copy private samples into shared plugin files, a public repository or an unapproved external service. Ask before persisting new personal style information. Respect a requested no-memory workflow.

House style is the default for all users of this skill. The user's explicit current decisions and verified venue requirements constrain it. Resolve substantive conflicts rather than silently adopting punctuation, citation style or reporting conventions from a sample. A casual chat voice does not establish the manuscript's register. Keep Thai discussion and English manuscript style distinct.

Memory is not evidence for a sample size, experimental setting or result. Reopen the authoritative file and reconcile versions. An AI-generated draft is not author approval. Only explicit acceptance or an attributable author correction can promote a new preference. Generic statements such as 'looks good' must not be stretched into approval of every scientific detail. When prior samples are unavailable, use the moderately formal lecture-like research voice without blocking the entire paper.

## R43 Complete the artifact, not only the text

Prepare only visuals that answer a scientific question. Photograph actual environments and apparatus, capture the actual UI, draw editable source-linked system diagrams, and plot approved data with reproducible code. Ask for missing originals. Existing rules against substitutes and generative changes to evidence still apply. Plan panel labels, captions, uncertainty and readability at the target column width before export.

Cross-check definitions and equations with code revision, functions, configurations and tests. Explain uncertainty and unresolved discrepancies. Formatting changes must not silently change scientific code or equations. Reuse the existing equation-code map and figure manifest rather than introducing competing copies.

For an existing Word manuscript, apply Word-first preservation before any text change. For a new Word paper, work from a copy of the verified venue template. An authorized programmatic new-document draft remains provisional until native Word inspection. Do not let ARS format-convert rebuild an existing Word master through Pandoc. LaTeX-only work follows its actual compiler and venue template. Never impose Word conversion where it was not requested.

Deliver the manuscript, necessary editable figures, plot data/code, references and requested document formats. Keep source registers, private style profiles, search records and quality reports outside submission files. Do not create placeholder files to simulate completion. Apply anonymity to the saved files and supplements, including metadata and headers. Native Word page count and every final page must be checked when DOCX is required. Recheck after the last layout-affecting save.

Use [full-paper-run.json](../assets/full-paper-run.json) as a blank checkpoint record and [ars-handoff.md](../assets/ars-handoff.md) when coordinating agents. A consistent record is not evidence that its checks ran. The optional auditor checks record completeness only, not scientific truth or author likeness. Mark unresolved checks honestly. Full-paper drafting does not remove researcher decisions, ARS confirmation points or venue AI-use disclosure.
