# ใช้ ARS ร่วมกับ Humanizer สำหรับงานวิจัย

คู่มือนี้เชื่อมขั้นตอนผ่านคำสั่ง ไม่ใช่ hook ที่บังคับการทำงาน ไม่ได้รวม plugin อัตโนมัติ และยังไม่ใช่ผลทดสอบร่วมกันครบกระบวนการ ต้องอ่าน dependency ที่ติดตั้งจริงก่อนใช้ รุ่นและตำแหน่งต้นทางที่ตรวจอยู่ใน [integrations.json](../provenance/integrations.json) ARS เป็น dependency แยก ไม่ได้ถูกคัดลอกเข้าแพ็กเกจนี้

## จุดเริ่มและหน้าที่

ใน Claude Code คำสั่ง `ars-full` ที่ตรวจจากต้นทางเรียก `academic-research-skills:academic-pipeline` ผ่าน Skill tool โดยตัวคำสั่งปิดการเรียกจากโมเดลไว้ ห้ามเรียก ars-full เองเป็น Skill และห้ามใช้สรุปสั้นในคำสั่งแทนคู่มือ pipeline จริง ต้องค้นชื่อที่มีอยู่ในระบบก่อนเรียก คำสั่งของเรา `/research-humanizer:research-full` โหลด research-paper-craft ก่อนแล้วประสานงาน ผู้ใช้จะเรียก `/academic-research-skills:ars-full` พร้อมระบุให้ใช้ research-paper-craft ตั้งแต่ขั้นแรกก็ได้

ถ้าไม่ได้ติดตั้ง ARS หรืออ่านไฟล์จำเป็นไม่ได้ ให้หยุดส่วน ARS และบอก dependency ที่ขาด ห้ามทำ pipeline เองแล้วเรียกว่า ARS เสนอใช้โหมด full-paper แบบเดี่ยวโดยแยกชื่อให้ชัด ห้ามติดตั้งแพ็กเกจ เปิด hook เปลี่ยนความจำรวม หรือส่งบทความไปโมเดลอื่นโดยไม่ได้อนุญาต

Codex มีชุด ARS แยกชื่อ `Imbad0202/academic-research-skills-codex` ใช้จุดเริ่ม `academic-research-suite` และชื่อทางลัด ars-* ต้องอ่านตัวนำทางที่ติดตั้งจริง ไม่ใช้ไฟล์คำสั่ง สภาพแวดล้อม ชื่อ agent หรือ hook ของ Claude แทน การนำเข้า skill ในบัญชี แชตทั่วไป desktop และ CLI มีความสามารถไม่เท่ากัน บันทึกเครื่องมือกับการควบคุมที่ใช้ได้จริง ตัวเชื่อมนี้ยังไม่ได้รับรองการทำงานผ่าน host จริง

ARS ควบคุมลำดับงาน สถานะ การตรวจหลักฐาน การทบทวน และจุดยืนยัน ส่วน Research Humanizer กำหนดสำนวนและการตรวจภายในขั้นเหล่านั้น ห้ามเปิดสอง pipeline แข่งกัน ทำทะเบียนหลักซ้ำ สร้างคำอนุมัติแทนผู้ใช้ หรืออ้างว่าเปิดการตรวจเสริมที่ไม่ได้รัน เลือก full drafting ในช่วง WRITE แต่ไม่ลบจุดยืนยันของผู้วิจัย การจำลอง reviewer ไม่ใช่การตอบรับจากผู้ประเมินจริง

## ส่งข้อกำหนดไปทุกขั้น

จัด [บันทึกส่งต่องาน](../assets/ars-handoff.md) แบบส่วนตัว ระบุรุ่นข้อมูล การตัดสินใจ กฎสำนวน Word ต้นฉบับหรือแม่แบบ พื้นที่ที่เขียนไฟล์ได้ แผนวรรณกรรมและ metric คำขอภาพจริง บริบทผู้เขียน และข้อมูลที่ยังขาด ส่งตำแหน่งไฟล์จริงให้ writer, visualization agent, reviewer และ formatter ทุกตัว พร้อมคู่มือช่วงที่ต้องอ่านและขอให้ระบุว่าอ่านอะไรแล้ว ห้ามถือว่า agent ลูกเห็นแชตหรือความจำของตัวหลักทั้งหมด ถ้าระบบส่งบริบทต่อไม่ได้ ให้บอกข้อจำกัดและตรวจชิ้นงานที่ส่งกลับเอง ไม่อ้างว่าบังคับใช้ได้แล้ว

| ช่วงของ ARS | หน้าที่ของ Research Humanizer |
| --- | --- |
| ค้นและรับงาน | ยืนยันรุ่นงาน แหล่งข้อมูล คำถาม แหล่งตีพิมพ์ ความเป็นส่วนตัว และสำนวนผู้เขียน ค้นต้นฉบับวิจัยและอ่านตัวอย่าง |
| ก่อนเขียน | วางแผนหลักฐาน metric และภาพ ถามต้นฉบับที่ขาดกับการตัดสินใจสำคัญ อ่านกฎสำนวนก่อนย่อหน้าแรก |
| เขียนและสร้างภาพ | ร่างครบทุกส่วนที่เกี่ยวข้อง ผูกข้อกล่าวอ้าง สัญกรณ์ และภาพกับหลักฐาน ใช้ภาพจริงและกราฟที่ทำซ้ำได้ |
| ตรวจหลักฐานและทบทวน | รักษาจุดตรวจและยืนยันของ ARS เทียบสิ่งที่แก้กับต้นทางและโค้ด บันทึกสิ่งที่ไม่มีหลักฐาน |
| แก้และทบทวนซ้ำ | ตรวจตัวเลข อ้างอิง metric แผนภาพ และสรุปทุกจุดที่ได้รับผล รักษาความไม่แน่นอนที่จำเป็น |
| จัดไฟล์สุดท้าย | ใช้ Word-first ดูไฟล์ที่บันทึกจริง ตรวจปกปิดชื่อ และระบุสิ่งค้าง |
| บันทึกกระบวนการและส่งมอบ | บอกเครื่องมือ การอนุมัติ แหล่งข้อมูล การค้น และข้อจำกัดที่เกิดจริง แยกจากบทความ |

ก่อนส่งงานให้ agent ต้องแนบโหมด full-paper กับข้อกำหนดแหล่งข้อมูล เมื่อได้งานกลับให้ตรวจตามข้อกำหนดนั้น ข้อความที่ writer บอกว่าผ่านไม่ใช่หลักฐานตรวจอิสระ ทุกช่วงต้องรักษาวิธียืนยันของ ARS ไม่สร้างการอนุมัติเพื่อให้ดูทำเร็ว

## แก้ข้อขัดแย้งที่ทราบ

ARS รองรับ Markdown, LaTeX และ DOCX ผ่าน Pandoc เมื่อมี Word ต้นฉบับอยู่แล้ว ห้ามแปลงเป็นสิ่งทดแทนการแก้ในไฟล์จริง ให้จัดขั้นสุดท้ายผ่าน Word-first ที่อนุญาต หรือส่ง review draft พร้อมแผนแก้ตามตำแหน่ง การสร้าง DOCX ใหม่จากแม่แบบที่อนุมัติอาจใช้การแปลงที่ได้รับอนุญาต แต่ต้องตรวจ Word จริงก่อนยืนยัน งาน LaTeX อย่างเดียวให้ตรวจผลคอมไพล์จริง ไม่แปลงต้นฉบับเดิมเพียงเพื่อให้ตรงค่าเริ่มต้นของเครื่องมือ

อ่านข้อกำหนดอ้างอิงของแหล่งตีพิมพ์จริง ARS main ที่ตรวจมีข้อจำกัดชั่วคราวต่อการแก้อ้างอิงอัตโนมัตินอก APA และชุด Codex อาจอ้างรุ่นก่อนหน้า ห้ามอ้างว่า IEEE หรือ Vancouver ถูกต้องจากตัวตรวจทั่วไป ต้องดู metadata ต้นทางและเกณฑ์เฉพาะ บันทึกรุ่น dependency ที่ใช้จริง ไม่เดาจากคู่มือนี้

## ปรับ Humanizer ของ Aboudjem ให้เหมาะกับ research

[Aboudjem/humanizer-skill](https://github.com/Aboudjem/humanizer-skill) เป็นแหล่งแนวคิดที่ตรวจแล้ว ไม่ใช่ dependency บังคับ และแพ็กเกจนี้ไม่ได้เปิดค่าเริ่มต้นการเขียนทั่วไปของเขา ต้นทางใช้ MIT เก็บข้อความสิทธิไว้ใน [aboudjem-humanizer-MIT.txt](../licenses/aboudjem-humanizer-MIT.txt) ส่วน Humanizer ต้นฉบับของ blader และเครดิตเดิมยังแยกเก็บครบ

| แนวทางทั่วไป | วิธีใช้กับงานวิจัย |
| --- | --- |
| เขียนเฉพาะเจาะจงแทนคำอวย | เพิ่มรายละเอียดจากหลักฐานจริงเท่านั้น ถ้าขาดให้ถาม |
| สำนวนและบริบท | ใช้คำยืนยันกับตัวอย่างที่ระบุเจ้าของได้ แยกต่อผู้วิจัย ห้ามแต่งบุคลิก เรื่องเล่า หรือความเห็น |
| คำย่อ เศษประโยค และจังหวะเน้น | ไม่ใช้ contractions หรือเศษประโยคเพื่อความเท่ ใช้ประโยคสมบูรณ์ค่อนทางการ |
| ตัดคำเผื่อความไม่แน่นอนอย่างแรง | เก็บความไม่แน่นอน ผลเชิงลบ ขอบเขตกลุ่มศึกษา และภาษาของความสัมพันธ์ที่ไม่ใช่เหตุและผล |
| เป้าหมายความแปรผันของประโยคหรือคะแนน AI | ไม่ปรับความยาวประโยค คำหายาก หรือ AI-tell score เพื่อให้ผ่านตัวตรวจ ให้ความหมายและการอ่านเป็นหลัก |
| คำซ้ำและประโยคถูกกระทำ | เก็บศัพท์เฉพาะ คำซ้ำที่จำเป็น และประโยคถูกกระทำที่เหมาะกับการรายงานวิทยาศาสตร์ |
| ล้างรหัสอ้างอิงและข้อความรอเติม | เชื่อมอ้างอิงกับแหล่งจริง เก็บเครื่องหมายข้อมูลขาดในร่าง ไม่ลบทิ้งเพื่อให้ดูเสร็จ |
| ล้าง Unicode | ตรวจตามภาษาและคณิตศาสตร์ ห้ามลบอักษรกรีก วรรณยุกต์ไทย ช่องว่างผูกหน่วย หรือสัญลักษณ์จริงแบบทั้งเอกสาร |
| ข้อสรุปลอยและย่อหน้าสลับที่กันได้ | ให้แต่ละย่อหน้าทำหน้าที่ในเหตุผลของงาน จบด้วยข้อสรุปและขอบเขตที่มีหลักฐาน |

ถ้าติดตั้ง humanizer ทั่วไปด้วย ห้ามรันการเขียนใหม่แบบไม่จำกัดหลังตรวจวิจัยเสร็จ ใช้ข้อเสนอของมันเป็นจุดให้ทบทวน กลับมาใช้ข้อกำหนด research และตรวจข้อกล่าวอ้างที่กระทบ คะแนนสำนวน 0 ถึง 100 ไม่ใช่โอกาสที่คนเขียน ไม่ใช่เกรดคุณภาพวิทยาศาสตร์ และไม่ใช่เหตุผลให้เปลี่ยนหลักฐาน

## ขอบเขตสิทธิและหลักฐานการทำงาน

ARS ใช้ CC BY-NC 4.0 ต้องติดตั้งแยกและปฏิบัติตามสิทธิของเจ้าของ MIT ของเราไม่เปลี่ยนสิทธิ ARS และไม่ลบเงื่อนไขห้ามใช้เชิงพาณิชย์ ชุดนี้ไม่บรรจุซอร์ส workflow สคริปต์ หรือภาพของ ARS ตัวเชื่อมอธิบายจุดเรียกใช้และเพิ่มข้อกำหนดงานวิจัยที่เขียนใหม่ ไม่อ้างว่าเจ้าของต้นทางทั้งสองรับรองโครงการเรา

การทดสอบในเครื่องตรวจไฟล์และบันทึก ไม่ใช่การรัน ARS จริง การทดสอบร่วมต้องใช้ host ที่อนุญาต บันทึกรุ่นทั้งสอง ยืนยันการอ่าน resource รันตัวอย่าง full-paper ที่เปิดเผยได้ด้วยเครื่องมือจริง เก็บข้อความจุดยืนยันและดูชิ้นงานทุกไฟล์ ทดสอบข้อมูลขาด แหล่งเข้าไม่ได้ โค้ดขัดกัน สมการเสีย ไม่มี Word และไม่มีภาพจริง ห้ามเขียนคำตอบในอุดมคติแล้วบันทึกเป็นผลจากโมเดล
