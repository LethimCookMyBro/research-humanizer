# ใช้เครื่องหมายตามหน้าที่ทางวิชาการ

อ่านร่วมกับคู่มือสำนวนก่อนร่างหรือแก้บทความ ตรวจคำบรรยายภาพ ข้อความในกราฟ หมายเหตุตาราง และป้ายในภาพรวมระบบด้วย ข้อห้ามเดิมยังมีผล กฎนี้ใช้ปรับงานเขียน ไม่ใช้ตัดสินว่าใครเป็นผู้เขียน

## R47 ตรวจเครื่องหมายตามหน้าที่

ให้แต่ละประโยคมีประเด็นหลักที่ชัด หากประโยครวมวิธีทำ ผล และการตีความไว้ด้วยกัน ให้แยกตามหน้าที่ตั้งแต่ตอนร่าง ไม่รอเขียนประโยคยาวแล้วค่อยลบลูกน้ำ ต้องรักษาเงื่อนไขและระดับความไม่แน่ใจให้ติดกับข้อกล่าวอ้างเดิม

อย่าลบลูกน้ำทั้งหมด เก็บตำแหน่งที่จำเป็นต่อไวยากรณ์และรายการที่มีหลายสิ่งจริง การเติมหรือลบลูกน้ำอาจเปลี่ยนว่าข้อความขยายครอบคลุมสิ่งใด อย่าเปลี่ยนลูกน้ำทุกตัวเป็น and อย่าใช้ semicolon colon ขีดยาว หรือวงเล็บแทนเพื่อคงประโยคยาวเดิม เพราะยังไม่ได้แก้โครงสร้างและอาจผิดข้อห้ามที่กำหนด

### แยกเครื่องหมายที่รกออกจากเครื่องหมายที่จำเป็น

| สิ่งที่ตรวจ | ส่วนที่ควรทบทวน | ส่วนที่ต้องรักษาเมื่อมีความหมาย |
| --- | --- | --- |
| ลูกน้ำ | ประโยคร้อยหลายใจความ คำอธิบายแทรก และรายการที่ปนหลายหน้าที่ | ไวยากรณ์ รายการจริง อ้างอิง และการแบ่งหลักตัวเลข |
| ยัติภังค์และขีดยาว | ขีดเว้นวรรคที่ใช้แทนคำเชื่อม หรือป้ายที่อัดคำด้วยขีด | คำประสม ชื่อเฉพาะ รหัส ค่าอย่าง -0.5 เครื่องหมายลบ และช่วงทางเทคนิคที่จำเป็น |
| เครื่องหมายเท่ากับ บวก และ & | การใช้สัญลักษณ์แทนความสัมพันธ์ที่ยังไม่ได้อธิบาย | สมการอย่าง n = 6 นิยาม และชื่อที่ต้องสะกดตรง |
| ลูกศร | การสื่อเหตุและผลหรือขั้นตอนที่หลักฐานไม่ได้รองรับ | เส้นทางระบบจริงและความสัมพันธ์ทางคณิตศาสตร์ที่นิยามแล้ว |
| เครื่องหมาย / | คำย่อความสัมพันธ์ที่กำกวม เช่น and/or หรือ guidance/feedback | หน่วย อัตราส่วน พาธ URL และชื่อทางเทคนิค |
| จุด | จุดซ้ำ คำโดดหลายคำที่คั่นด้วยจุด หรือจบประโยคไม่สม่ำเสมอ | จุดจบประโยคที่สมบูรณ์ ทศนิยม เลขรุ่น นามสกุลไฟล์ และคำย่อ |
| วงเล็บ | คำอธิบายแทรกหลายชุดหรือซ้อนกัน | อ้างอิง เลขสมการ การแนะนำคำย่อที่จำเป็น และการจัดกลุ่มในสูตร |
| จุดไข่ปลาและเครื่องหมายย้ำ | การละข้อความอย่างกำกวม การสร้างจังหวะตื่นเต้น และ !! หรือ ?? | การละข้อความอ้างตรง ลำดับทางคณิตศาสตร์ และข้อความต้นฉบับ |
| เส้นคั่นและรูปแบบข้อความ | เส้นตกแต่ง ตัวหนาซ้ำ และสัญลักษณ์ที่ไม่มีหน้าที่อธิบาย | โครงสร้าง Markdown ไวยากรณ์ต้นฉบับ และข้อกำหนดแม่แบบ |

เนื้อความควรใช้ประโยคที่สมบูรณ์ ป้ายในกราฟหรือภาพรวมใช้วลีสั้นได้ ไม่บังคับให้ทุกป้ายเป็นประโยคเต็ม แต่เนื้อความต้องไม่กลายเป็นคำโดดที่ขาดความสัมพันธ์ จุดจบประโยคไม่ได้เป็นสิ่งต้องห้าม หลังแบ่งประโยคให้ตรวจคำปฏิเสธ เงื่อนไข ประชากรที่ศึกษา หน่วย การเปรียบเทียบ และอ้างอิง รวมถึงตรวจว่าความหมายเรื่องเกิดพร้อมกันหรือลำดับเหตุการณ์ยังอยู่ครบ ห้ามเติมลำดับหรือเหตุผลที่ไม่มีในหลักฐาน

ข้อความภาษาไทยไม่ต้องเติมลูกน้ำและจุดตามภาษาอังกฤษ ให้ใช้การแบ่งวลีและย่อหน้าที่เป็นธรรมชาติ รักษาตัวอักษรและวรรณยุกต์ อย่าแปลง Unicode ทางวิทยาศาสตร์หรือลบอักขระที่มองไม่เห็นทั้งเอกสาร Word อัตโนมัติ หากสงสัยว่าสัญลักษณ์เสียต้องเทียบต้นฉบับก่อน

### ขั้นตอนตรวจ

อ่านทั้งย่อหน้าแล้วระบุข้อกล่าวอ้างกับเงื่อนไข แก้เฉพาะโครงสร้างที่เครื่องหมายทำให้อ่านยาก เทียบประโยคใหม่กับหลักฐาน จากนั้นอ่านออกเสียงเพื่อตรวจว่าประโยคสมบูรณ์และเชื่อมกันดี หยุดเมื่อแก้ปัญหาที่พบแล้ว ข้อความที่ดีอยู่แล้วคงเดิมได้

ตรวจหลังร่างหรือแก้แต่ละส่วน และตรวจอีกครั้งเมื่อรวมบทความ ส่งข้อกำหนดนี้ให้ผู้ร่าง ผู้ตรวจ และผู้จัดรูปแบบใน ARS ด้วย ขั้นตอนนี้ไม่แทนการตรวจ Word ไม่อนุญาตให้เปลี่ยนสูตร และไม่ยกเลิกกฎถามผู้วิจัยเมื่อต้นฉบับขาด

### ตัวอย่างที่ไม่แต่งผลเพิ่ม

ตัวอย่างสมมติสำหรับสอน ต้นทางบอกเพียงว่าระบบบันทึกการกระทำและการดูคำแนะนำ เก็บสถานะชิ้นงาน และส่งออกบันทึกการทดลอง ไม่ได้ให้ลำดับการทำงานหรือผลด้านประสิทธิภาพ

ก่อนแก้

> The system records actions, tracks reference use, stores workpiece states, and exports the session log.

ฉบับแก้ที่ใช้ได้

> The system records actions and reference use. It also stores workpiece states and exports the session log.

เก็บการทำงานทั้งสี่ส่วน อย่าเติม then เพราะไม่มีข้อมูลลำดับ หากพบข้อความ Feedback = successful learning ต้องตรวจว่าหลักฐานรองรับความสัมพันธ์หรือไม่ ห้ามเปลี่ยนเป็นประโยคที่ฟังเป็นเหตุเป็นผลแล้วถือว่าข้ออ้างนั้นจริง

### ขอบเขตตัวตรวจ

ใช้ตัวตรวจเดิม lint_manuscript.py ได้ โดย COMMA_DENSITY_REVIEW จะแจ้งเมื่อประโยคที่แยกได้มีลูกน้ำเนื้อความตั้งแต่ 3 ตัวขึ้นไป นี่เป็นจุดให้ทบทวน ไม่ใช่คำตัดสินว่าผิดไวยากรณ์หรือโควตาลูกน้ำ การมีรายการสี่อย่างอาจจำเป็น ตัวตรวจไม่นับลูกน้ำในตัวเลขอย่าง 1,000 เมื่อรู้จักรูปแบบ และรวมข้อความที่ตัดบรรทัดแต่ยังเป็นย่อหน้าเดียวกันก่อนตรวจ

เพิ่มการทบทวนคำเชื่อมระหว่างประโยค ขีดเว้นวรรค สัญลักษณ์แทนคำ เครื่องหมาย / จุดซ้ำ จุดไข่ปลา วงเล็บแทรก และคำโดดคั่นด้วยจุดบางรูปแบบ ประโยคภาษาอังกฤษที่มี and อย่างน้อย 4 ครั้งและมีอย่างน้อย 30 คำตามการแยกคำแบบอังกฤษจะถูกเสนอให้ทบทวนด้วย เกณฑ์เหล่านี้เป็นตัวช่วยคัดจุดตรวจ ไม่ใช่ตัววิเคราะห์ไวยากรณ์หรือคะแนนคุณภาพโมเดล

ตัวตรวจยกเว้นโค้ด สมการ ส่วนอ้างอิง ตัวเลข อ้างอิงในเนื้อหา ข้อความอ้างด้วยอัญประกาศคู่ และไวยากรณ์ทางเทคนิคบางรูปแบบที่รู้จัก ไม่ครอบคลุมทุกคำย่อ ทุกชื่อ ทุกระบบอ้างอิง หรือ Markdown ทุกชนิด ยังไม่แยกประโยคภาษาไทยอย่างสมบูรณ์และไม่เห็นหน้าจริงใน Word อ่านรายการ not_checked ในรายงาน JSON และตรวจคำทางเทคนิคที่ไม่รู้จักด้วยคน ห้ามแก้เพียงเพื่อให้ตัวเตือนหาย

คำเตือนแบบใหม่ใช้ระดับ review ข้อห้ามเดิมที่ชัดเจนยังเป็น required_fix ตัวเลือก --fail-on-findings ทำให้คำเตือนที่ต้องทบทวนมีสถานะออกไม่สำเร็จ ส่วน --fail-on-errors ยังตรวจเฉพาะรายการที่ต้องแก้ตามเดิม สถานะออกเป็นศูนย์ไม่ได้รับรองว่างานเขียนผ่าน ต้องตรวจรายการที่แจ้งและบันทึกว่าแก้แล้วหรือมีเหตุผลให้คงไว้ก่อนรายงานว่าตรวจสำนวนครบ เครื่องมือไม่แก้ข้อความอัตโนมัติและไม่ให้คะแนนความเป็น AI

### แหล่งประกอบและขอบเขต

ตรวจแหล่งอ้างอิงวันที่ 17 พฤศจิกายน 2026 แหล่งเหล่านี้อธิบายหน้าที่เครื่องหมายและแนวทางบรรณาธิการ ส่วนเกณฑ์จำนวนกับข้อห้ามเป็นข้อตกลงของโครงการ ไม่ใช่เกณฑ์ตรวจ AI ที่พิสูจน์แล้วและไม่ได้หมายถึงการรับรองโครงการโดยแหล่งอ้างอิง
