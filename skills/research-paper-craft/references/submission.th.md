# การตรวจและเตรียมส่ง

อ่านเมื่อทำงานส่วนนี้ กฎหลักใน SKILL.md ยังมีผลตลอดงาน

## R24 จัดการจริยธรรม การเปิดเผย และฉบับปกปิดชื่อ

ตรวจข้อกำหนดเรื่องจริยธรรม ความยินยอม สิทธิใช้ข้อมูล การคุ้มครองข้อมูล ทุน ผลประโยชน์ทับซ้อน และการเปิดเผยการใช้ AI ที่เกี่ยวข้อง ห้ามแต่งการอนุมัติ เลขลงทะเบียน ข้อความยินยอม บทบาทผู้เขียน หรือข้อความขอบคุณทุน รายการที่ต้องให้ผู้เขียนยืนยันต้องยังเห็นชัด

ฉบับ anonymous ต้องลบข้อมูลระบุตัวตนทั้งในบทความและทุกไฟล์ที่จะส่ง ตรวจชื่อผู้เขียน สังกัด อีเมล คำขอบคุณ ทุน โลโก้ ถ้อยคำเฉพาะสถาบัน หัวกระดาษ ท้ายกระดาษ ลายน้ำ ลิงก์ เจ้าของคลังโค้ด ชื่อไฟล์ และเอกสารเสริม

ตรวจคุณสมบัติเอกสาร metadata ที่เพิ่มเอง ความเห็น ประวัติแก้ไข ข้อความซ่อน คำอธิบายภาพสำหรับการเข้าถึง วัตถุฝัง ข้อมูลในกราฟ ไฟล์แนบ EXIF หรือ XMP ของภาพ metadata ของ PDF ที่คั่นหน้า และตำแหน่งไฟล์ต้นทางตามความเกี่ยวข้อง ค้นทั้งชุดไฟล์ด้วยชื่อและรหัสที่รู้ การค้นข้อความอย่างเดียวไม่ใช่การตรวจปกปิดชื่อที่ครบถ้วน

ทำฉบับปกปิดชื่อแยกจากต้นฉบับระบุชื่อที่เก็บส่วนตัว รักษาหลักฐานสิทธิที่จำเป็น จัดการรายการติดตามการแก้ไขโดยพิจารณา ไม่ยอมรับทั้งหมดอัตโนมัติ ตรวจซ้ำหลังบันทึกหรือส่งออกครั้งสุดท้าย เพราะไฟล์ที่บันทึกอาจต่างจากสถานะที่เพิ่งตรวจ

ทำตามข้อกำหนดเรื่องการอ้างงานตนเองและไฟล์ปกปิดชื่อของแหล่งตีพิมพ์ ห้ามลบการให้เครดิตที่ถูกต้องหรือปลอมข้อมูลบรรณานุกรมเพื่อให้ดูไม่เปิดเผยตัวตน ตรวจว่าลิงก์แสดงอะไรกับผู้ประเมินที่ไม่มีสิทธิของเจ้าของ ห้ามเผยแพร่คลังโค้ดหรือส่งบทความโดยไม่มีคำสั่งอนุญาต

## R25 ตรวจเอกสารที่จัดหน้าจริง

ใช้แม่แบบเป้าหมายจริง รักษาสมการ ภาพ ตาราง อ้างอิง และการอ้างข้ามส่วนให้แก้ไขได้เมื่อรูปแบบรองรับ เก็บไฟล์ต้นฉบับและเขียนเวอร์ชันใหม่ด้วยชื่อที่แยกชัด

เมื่อส่งเป็น Word ต้องเปิด DOCX ฉบับสุดท้ายใน Microsoft Word อัปเดตฟิลด์และการอ้างข้ามส่วน ให้ Word คำนวณหน้าใหม่ บันทึกไฟล์ และจดจำนวนหน้าจริง ตรวจทุกหน้าในมุมมองจัดหน้าของ Word หรือ PDF ที่ส่งออกจาก Word ฉบับสุดท้ายเดียวกัน ต้องบันทึกว่าใช้วิธีใด ตรวจต้นและท้ายทุกหน้า ไม่ดูเพียงภาพย่อรวม

ตรวจหัวข้อ ระยะย่อหน้า บรรทัดโดดต้นหรือท้ายหน้า จุดตัดหน้า คอลัมน์ สมการ ตัวห้อย ตัวยก อักษรกรีก อักษรไทย ตาราง หัวตารางที่ซ้ำ คำบรรยาย อ้างอิง ความละเอียดภาพ และตำแหน่งยึดวัตถุ มองหาการตัดขอบ การซ้อนทับ หน้าว่างที่ไม่ตั้งใจ ฟอนต์ถูกแทน คำบรรยายหลุดจากภาพ และป้ายที่อ่านไม่ได้

นับหน้าตามกฎของแหล่งตีพิมพ์ ตรวจว่าอ้างอิง ภาคผนวก และเอกสารเสริมนับรวมหรือไม่ เมื่อส่งทั้ง DOCX และ PDF ต้องตรวจทั้งคู่ หลังแก้สิ่งที่กระทบหน้าต้องตรวจซ้ำ

ห้ามอ้างว่าตรวจใน Word จริงจากการประมาณจำนวนคำ ค่าจำนวนหน้าในคุณสมบัติไฟล์ python-docx LibreOffice โปรแกรมจัดหน้าอื่น หรือ PDF ที่ไม่ทราบแหล่ง การจัดหน้าด้วยเครื่องมืออื่นใช้ตรวจชั่วคราวได้ แต่ต้องระบุชื่อเครื่องมือและคงสถานะตรวจ Word ว่ายังไม่เสร็จ

หากผู้ใช้เลือกทำงานด้วย LaTeX หรือรูปแบบอื่นโดยเฉพาะ ให้คอมไพล์ด้วยแม่แบบที่ต้องใช้และตรวจทุกหน้าของไฟล์จริง ไม่ต้องแปลงไป Word โดยไม่จำเป็น หากการตรวจ Word เป็นเงื่อนไขบังคับแต่ไม่มี Word ให้ส่งเป็นร่างสำหรับตรวจพร้อมระบุสิ่งค้าง ห้ามเรียกว่าพร้อมส่ง

## R26 ทำงานผ่านจุดตรวจที่มีหลักฐาน

| จุดตรวจ | หลักฐานก่อนนำข้อกล่าวอ้างที่เกี่ยวข้องไปใช้ต่อ |
| --- | --- |
| ขอบเขตงาน | ระบุรูปแบบงาน แหล่งข้อมูล ภาษา และเรื่องที่ยังต้องตัดสินใจ |
| ชุดแหล่งข้อมูล | เชื่อมเวอร์ชันที่ใช้และบันทึกข้อขัดแย้ง |
| ข้อมูลจำเป็น | ถามผู้วิจัยเรื่องข้อมูลเฉพาะงานที่ขาดตาม R01 และบันทึกสถานะ |
| ฐานทางวิชาการ | ข้อหลักมีหลักฐาน ส่วนที่ไม่รองรับถูกตัดหรือทำเครื่องหมาย |
| วิธีและตัวเลข | วิธี สมการ โค้ด และผลที่กำหนดได้รับการตรวจความตรงกัน |
| ภาพ | ทุกภาพมีที่มาและผ่านการตรวจในขนาดจริง |
| ภาษา | รักษาความหมาย ตรวจสำนวน และตรวจสองภาษาเมื่อเกี่ยวข้อง |
| การส่งงาน | ตรวจข้อเปิดเผย อ้างอิง การปกปิดชื่อ และหน้าที่จัดจริง |

ใช้จุดตรวจตามขนาดงาน การแก้ย่อหน้าเดียวไม่ต้องสร้างชุดไฟล์ทั้งบทความ แต่การเขียนทั้งฉบับต้องตรวจทุกส่วนที่เกี่ยวข้อง รายการที่ไม่เกี่ยวข้องต้องบอกเหตุผล ห้ามทำเครื่องหมายผ่านในสิ่งที่ยังไม่ได้ตรวจ

เมื่อทำต่อไม่ได้เพราะข้อมูลจำเป็นขาด ให้ถามผู้วิจัยว่ามีต้นฉบับหรือไม่ตาม R01 และบอกว่ากระทบส่วนใด การบันทึกว่าขาดข้อมูลไม่ถือว่าได้ถามแล้ว ทำส่วนที่เป็นอิสระต่อได้ รักษาเครื่องหมายในร่างให้เห็น เช่น `[SOURCE REQUIRED]`, `[RESULT UNVERIFIED]` หรือ `[AUTHOR DECISION]` ห้ามแทนช่องว่างด้วยเนื้อหาที่ดูน่าเชื่อเพื่อให้เอกสารดูเสร็จ

เกลาภาษาหลังสาระทางวิชาการนิ่งแล้ว เทียบฉบับแก้กับฉบับที่ผูกหลักฐาน ตรวจตัวเลข ขอบเขต เหตุและผล ความไม่แน่นอน ข้อยกเว้น อ้างอิง และศัพท์เทคนิคซ้ำเมื่อมีการเขียนใหม่มาก

## R27 แยกบทความออกจากบันทึกตรวจ

ส่งบทความและไฟล์ที่สร้างจริงตามคำขอ รวมต้นฉบับแก้ไขได้ ภาพและต้นฉบับภาพ บรรณานุกรม โค้ดวิเคราะห์หรือสร้างกราฟที่จำเป็น และเอกสารจัดหน้าเมื่อมี ห้ามสร้างไฟล์ว่างเพื่อให้ชุดงานดูครบ

แยกบันทึกภายในไว้ในโฟลเดอร์ทำงานหรือตรวจงาน เช่น ทะเบียนแหล่งข้อมูล ข้อกล่าวอ้าง ตัวเลข ภาพ สัญกรณ์ การตรวจอ้างอิง การตัดสินใจ และรายงานตรวจ ห้ามเผลอรวมข้อมูลดิบส่วนตัว ตารางเชื่อมตัวตน กุญแจ API ข้อมูลผู้เขียนที่ซ่อน หรือความเห็นภายในลงในชุดส่ง

ข้อความส่งงานควรระบุไฟล์ที่เสร็จ สิ่งที่ตรวจแล้ว ปัญหาที่ยังค้าง และเรื่องที่ผู้เขียนต้องทบทวน ตัวบทความต้องไม่มีข้อความแบบแชต คำเล่าวิธีทำงาน หรือบันทึกตรวจที่ไม่เกี่ยวกับผู้อ่าน ไม่ส่งทั้งร่างหยาบและฉบับสุดท้ายเมื่อผู้ใช้ไม่ได้ขอ

ระบุสถานะงานชัด `Working draft` คือยังขาดข้อมูลทางวิชาการ `Review draft` คือประกอบเนื้อหาที่รองรับแล้วแต่ยังมีการตรวจหรือการอนุมัติค้าง `Submission candidate` คือผ่านการตรวจเทคนิคและรูปแบบที่เกี่ยวข้องแล้ว แต่ผู้เขียนยังเป็นผู้ตัดสินใจส่ง ห้ามรับรองว่าจะได้รับตีพิมพ์หรือผ่านทุกข้อกำหนดโดยอัตโนมัติ

## R28 ใช้สถานะผ่าน ไม่ผ่าน ยังไม่ตรวจ และไม่เกี่ยวข้อง

ก่อนส่ง ตรวจหลักฐาน วิธี คณิตศาสตร์ สถิติ อ้างอิง ภาพ สำนวน การทำซ้ำ การปกปิดชื่อ และหน้าที่จัดจริง บันทึกรายการตรวจ ไฟล์ หลักฐาน ผล และสิ่งที่ต้องแก้

ปัญหาที่ห้ามข้าม ได้แก่ แหล่งหรือผลที่แต่งขึ้น ข้อกล่าวอ้างหลักไม่มีหลักฐาน วิธีไม่ตรงกับผลโดยยังไม่คลี่คลาย ภาพชวนเข้าใจผิด การคำนวณหลักผิด ข้อเปิดเผยบังคับยังขาด หรือข้อมูลผู้เขียนหลุดในฉบับที่ต้องปกปิด หากงานกำหนดให้ตรวจ Word แต่ยังไม่ตรวจจำนวนหน้าหรือยังดูหน้าสุดท้ายไม่ครบ ต้องไม่เรียกเป็นฉบับที่ผ่านการตรวจสำหรับส่ง

ข้อเตือนอาจเป็นสำนวนเล็กน้อย ย่อหน้าที่ยาวแต่มีหลักฐานครบ หรือภาพที่ปรับให้อ่านง่ายขึ้นได้ จัดระดับตามผลต่อความหมายทางวิชาการและข้อกำหนดการส่ง ไม่ใช่ความง่ายในการแก้

ห้ามให้ร้อยละความเป็น AI หรือคะแนนคุณภาพที่ไม่มีหลักรองรับ ระบุปัญหาและวิธีแก้เฉพาะจุด เครื่องมือตรวจข้อความช่วยหาเครื่องหมายหรือช่องว่างในร่างได้ แต่รับรองความถูกต้องทางวิทยาศาสตร์ การไม่ลอกผลงาน การปกปิดชื่อ การจัดหน้าใน Word หรือผู้เขียนที่เป็นมนุษย์ไม่ได้

ใช้ผู้ตรวจหรือเครื่องมืออิสระเมื่อมีจริง หากไม่มี ให้ตรวจซ้ำอีกครั้งด้วยตนเองและรายงานตามนั้น ห้ามแต่งว่ามีผู้ตรวจคนที่สอง มีการทดสอบกับ agent แล้ว หรือมีการเรียกเครื่องมือที่ไม่ได้เกิดขึ้น

ตรวจว่าได้ถามผู้วิจัยเรื่องข้อมูลจำเป็นที่ขาดทุกข้อแล้ว ใช้คำตอบเดิมโดยไม่ถามซ้ำ และไม่มีสิ่งทดแทนที่ไม่ได้รับอนุญาตแทรกในข้อความหรือภาพ ข้อมูลจำเป็นที่ยังไม่คลี่คลายทำให้เรียกงานเป็นฉบับผ่านการตรวจสำหรับส่งไม่ได้ ข้อตัดสินของผู้วิจัยใช้ยุติเรื่องภาพประกอบที่ไม่จำเป็นได้ แต่ใช้ยืนยันหลักฐานวิจัยที่แต่งขึ้นไม่ได้

ในการตรวจภาษา ข้อห้ามชัดของสำนวนเป็นรายการต้องแก้ `required_fix` ไม่ใช่คำแนะนำตกแต่งที่ข้ามได้ ข้อความที่มีหลักฐานแต่ยืดเยื้อเป็นจุดให้ทบทวน การอ่านโครงสร้างไม่ครบหรือเข้าถึงแหล่งไม่ได้ไม่ถือว่าผ่านสำนวน แยกขอบเขตที่ตรวจแล้วกับยังไม่ตรวจ เครื่องหมายรอข้อมูลต้องยังถูกตรวจพบแม้อยู่ในโค้ดหรือสมการ ตัวตรวจห้ามให้ผ่านด้วยการซ่อนช่วงที่อ่านไม่ได้
