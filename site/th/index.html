Research Humanizer เป็น skill โอเพนซอร์สสำหรับงานเขียนวิจัยบน Claude Code และ Codex ใช้ร่วมกับ Academic Research Skills หรือ ARS เพื่อกำกับสำนวนและหลักฐานตั้งแต่ร่างแรกจนถึงต้นฉบับเต็ม

ใช้ข้อกำหนดเดียวกันตลอดบทความ

ใช้คู่กับ ARS สำหรับกระบวนการเต็ม หรือใช้ skill หลักแยกก็ได้ การตัดสินใจและจุดยืนยันที่จำเป็นยังเป็นหน้าที่ของผู้วิจัย

  1. 01

    เข้าใจงานจริง

    อ่านไฟล์งาน ข้อมูลต้นทาง โค้ด และผลที่ยืนยันแล้ว ถามเมื่อข้อมูลขาดหรือเวอร์ชันขัดกัน

  2. 02

    อ่านก่อนร่าง

    ค้น paper ที่เกี่ยวข้อง ข้อกำหนดทางการของแหล่งตีพิมพ์ และนิยามตัวชี้วัด บันทึกแหล่งอ้างอิงแยกจากผลของงานนี้

  3. 03

    ร่างด้วยสำนวนที่เหมาะ

    เขียนทุกส่วนที่จำเป็นด้วยภาษาวิจัยที่อ่านเข้าใจ ใช้ตัวอย่างและบริบทที่ผู้เขียนยอมรับเมื่อมี

  4. 04

    ตรวจไฟล์ที่บันทึกแล้ว

    ตรวจข้อกล่าวอ้าง สมการ กราฟ และรูปแบบเอกสาร แยกสิ่งที่ผ่านแล้วออกจากสิ่งที่ยังไม่ได้ยืนยัน

ติดตั้ง skill แล้วใช้กับไฟล์งานจริง

เลือกเครื่องมือที่ใช้อยู่ด้านล่าง การทำ full paper ผ่าน ARS ต้องติดตั้ง ARS แยก Research Humanizer ไม่ติดตั้งให้โดยอัตโนมัติ

Claude Code

พิมพ์ใน Claude Code ทีละคำสั่ง

/plugin marketplace add LethimCookMyBro/research-humanizer
/plugin install research-humanizer@research-humanizer

Codex CLI

รันใน terminal ไม่ใช่ช่องแชตของ Codex

codex plugin marketplace add LethimCookMyBro/research-humanizer
codex plugin add research-humanizer@research-humanizer
เพิ่ม ARS สำหรับกระบวนการเขียนทั้งฉบับ

ARS ใช้สิทธิ CC BY-NC 4.0 แยกต่างหาก เงื่อนไขนั้นยังมีผลเมื่อใช้ร่วมกับโปรเจกต์ MIT นี้ Academic Research Skills

/plugin marketplace add Imbad0202/academic-research-skills
/plugin install academic-research-skills

เริ่มร่างทั้งฉบับใน Claude Code

/research-humanizer:research-full ร่างบทความทั้งฉบับจากไฟล์โปรเจกต์นี้ร่วมกับ ARS ค้น paper ที่เกี่ยวข้องและแม่แบบทางการ ใช้กฎสำนวนวิจัยตั้งแต่ร่างแรก ถามก่อนเมื่อข้อมูลหรือภาพจริงขาด และรักษาจุดยืนยันของผู้วิจัย

สำหรับ Codex ให้ติดตั้ง ARS-Codex แยก แล้วสั่งใช้ academic-research-suite ร่วมกับ research-paper-craft ARS-Codex

ติดตั้งแล้วแต่รุ่นยังเก่า ให้ตรวจต้นทางและเวอร์ชันที่ติดตั้งก่อนเปลี่ยนไฟล์ การมี GitHub Release ไม่ได้บังคับให้ plugin ที่ค้างในเครื่องอัปเดตเอง คู่มือติดตั้งและอัปเดต

ตัดคำลอย โดยไม่เปลี่ยนสาระ

ตัวอย่างที่เขียนเพื่ออธิบาย ไม่ใช่ผลทดสอบโมเดล ข้อมูลต้นทางระบุเพียงว่าวิธีนี้รวมข้อมูลเซนเซอร์ และยังไม่มีผลประเมิน

ร่างที่กล่าวเกินหลักฐาน

Our groundbreaking framework seamlessly integrates sensor measurements and demonstrates robust real-world performance.

ฉบับที่ตรงกับข้อมูลต้นทาง

The method combines sensor readings.

ข้อกล่าวอ้างเรื่องประสิทธิภาพต้องมีหลักฐาน จึงแจ้งผู้วิจัยแทนการเขียนให้น่าเชื่อขึ้น ส่วนข้อความที่ชัดและมีหลักฐานแล้วสามารถคงเดิมได้

ออกแบบตามข้อจำกัดของงานวิจัย

หลักฐานและอ้างอิง

โยงตัวเลขกลับไปยังชุดผลที่กำหนดและข้อมูลดิบ ตรวจว่าแหล่งอ้างอิงรองรับข้อกล่าวอ้างจริง

สมการและโค้ด

นิยามตัวแปรและหน่วย เชื่อมสูตรกับสิ่งที่คำนวณจริง และตรวจจุดที่ไม่ตรงกัน

กราฟและภาพต้นฉบับ

เก็บข้อมูลพล็อตกับสคริปต์ ขอภาพถ่ายหรือภาพหน้าจอจากงานจริงเมื่อเนื้อหาต้องใช้หลักฐานที่สังเกตได้

ภาพรวมระบบและอินโฟกราฟิก

ทุกส่วนและลูกศรต้องอธิบายวิธีจริง ไม่เพิ่มองค์ประกอบสมมติเพื่อให้ภาพดูดี

Word และฉบับปกปิดชื่อ

รักษาสไตล์ วัตถุสมการ และฟิลด์ ตรวจหน้าสุดท้ายและข้อมูลระบุตัวตนก่อนส่ง

สำนวนเจ้าของงาน

ใช้ตัวอย่างที่ยอมรับและบริบทที่เข้าถึงได้ ไม่แต่งความจำ ประสบการณ์ หรือเหตุผลส่วนตัว

สิ่งที่ควรรู้ก่อนใช้

ร่าง paper ทั้งฉบับได้ไหม

โหมด full-paper กำหนดให้ AI ร่างทุกส่วนที่จำเป็นจากข้อมูลที่ให้ แต่ไม่ได้เปลี่ยนหัวข้อให้กลายเป็นการทดลองที่ทำเสร็จแล้ว และไม่สร้างผลที่ยังไม่มี

ต่างจาก Humanizer ทั่วไปอย่างไร

ออกแบบสำหรับบทความวิจัยโดยเฉพาะ รักษาศัพท์เทคนิค ขอบเขต ความไม่แน่นอน อ้างอิง คณิตศาสตร์ และเงื่อนไขด้านหลักฐานขณะร่างและแก้

ต้องติดตั้ง ARS ไหม

ต้องติดตั้งแยกเฉพาะเมื่อเลือกเส้นทางที่ใช้ ARS ประสานงาน ส่วน skill research-paper-craft ใช้ร่าง แก้ หรือตรวจแบบแยกได้

รับรองว่าเหมือนคนเขียนหรือผ่านตัวตรวจ AI ไหม

ไม่รับรอง รูปแบบสำนวนไม่ใช่หลักฐานระบุผู้เขียน โครงการไม่ได้ตั้งเป้าหลบตัวตรวจ AI และต้องทำตามนโยบายเปิดเผยการใช้ AI ของแหล่งตีพิมพ์

ซ่อมรูปแบบ Word อัตโนมัติไหม

ไม่ใช่ ตัวตรวจ DOCX อ่านโครงสร้างอย่างเดียว ต้องตรวจไฟล์จริงใน Microsoft Word ก่อนอ้างว่าจำนวนหน้าและรูปแบบสุดท้ายผ่านแล้ว

ทดสอบอะไรแล้วบ้าง

รุ่น v2.3.4 มีชุดทดสอบซอฟต์แวร์และข้อกำหนดคำสั่ง แต่ยังไม่ได้สาธิตการใช้ ARS จริง คุณภาพทั้งบทความ และการซ่อม Word แบบครบกระบวนการสำหรับตัวเชื่อมนี้

เป็นรุ่น Preview ที่ระบุข้อจำกัดชัดเจน

การผ่านตัวตรวจไม่ใช่การรับรองความถูกต้องทางวิทยาศาสตร์หรือความพร้อมส่ง อ่านบันทึกการตรวจเพื่อดูสิ่งที่ทดสอบแล้ว ผู้วิจัยยังเป็นผู้รับผิดชอบผลงานที่ส่ง
